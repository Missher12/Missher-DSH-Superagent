# Git 团队并行执行

目标：同一 Git 项目的独立成员真正并行，依赖交付后汇总代码、解决冲突、实际检验，保留现有串行执行。

依据：用户已确认本轮先做并行与集成交付，并要求 macOS、Windows、Linux 安装使用。由本会话实施，不委派子代理。

边界：选择 Git 并行即授权插件在独立 worktree 内创建本地交付提交；不自动推送、不修改原项目工作树。已有任务沿用原模式。要求 Git 项目根目录、已有提交和干净的起始工作树。外部来源仍检查原目录及原权限；不开原生子代理。

实现：

- [x] `src/teams/git-workspaces.ts`：独立分支与目录、依赖合并、交付提交；真实 Git 仓库覆盖并行修改、中文空格路径、冲突、恢复与原文件保留。
- [x] 持久化 Git 计划与调度；成员在自身目录执行，最终集成实跑检查。调度、续作、外部回传及来源撤权回归通过。
- [x] 新建团队与通用设置增加执行方式；工作台显示目录/分支；交付文件按所属目录打开。实际宿主在 1280、960、760px 视口适配通过。
- [x] 成品预览下载、独立总指挥报告；完成后补充回原策划，保留原会话及附件，不重派无关成员。
- [x] macOS 日常 DSH 使用 Qwen3.7 Plus High 实测并行开发，交付 5 个文件、33 项测试通过，完成后两次补充接续通过。三平台 CI 各 59 项检查、类型与构建通过；Windows/Linux 桌面宿主未实测。

发布版本为 1.12.0；源码、安装包和日常安装以对应 Release 及实际安装记录为准。

关键失败场景：脏项目、合并冲突、完成后补充、停止/重启、外部来源撤权。不得为恢复覆盖用户文件或重写已有提交。

后续阶段：任务预算与长任务控制、可复用团队模板。MSE 仅在完成后记录已验证经验。
