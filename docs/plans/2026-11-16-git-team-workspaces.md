# Git 团队并行执行

目标：同一 Git 项目的独立成员真正并行，依赖交付后汇总代码、解决冲突、实际检验，保留现有串行执行。

依据：用户已确认本轮先做并行与集成交付，并要求 macOS、Windows、Linux 安装使用。由本会话实施，不委派子代理。

边界：选择 Git 并行即授权插件在独立 worktree 内创建本地交付提交；不自动推送、不修改原项目工作树。已有任务沿用原模式。要求 Git 项目根目录、已有提交和干净的起始工作树。外部来源仍检查原目录及原权限；不开原生子代理。

实现：

- [ ] `src/teams/git-workspaces.ts`：Git 参数调用、可恢复的独立分支/目录、依赖合并、交付提交。先用真实临时 Git 仓库验证并行修改、中文空格路径、冲突、重入、未提交原文件保留。
- [ ] `src/teams/local.ts` / `contracts.ts`：持久化 Git 计划；成员只在自身目录执行；依赖和最终汇总使用真实提交；冲突交给原成员处理；完成需要汇总后的实际检查。扩展 `tests/local-teams.spec.ts` 覆盖调度、续作及来源权限。
- [ ] 新建团队与通用设置增加执行方式；工作台显示目录/分支；交付文件按所属成员目录打开。保留原生表单与窄屏布局。
- [ ] 用户追加：集中展示成品与下载入口，策划通过后交接本团队总指挥，由总指挥原生会话生成最终报告并向原来源回传；历史成品仍可查看，运行中的旧任务不强制改变流程。
- [ ] macOS 本机 Git/DSH 实测；跨系统 CI 验证 Windows/Linux Git、路径、类型和构建。区分运行时测试与完整 DSH 宿主验收。
- [ ] 完成检查后更新版本、Git、含安装包的 Release 与日常 DSH。未验证平台如实说明。

关键失败场景：脏项目、合并冲突、完成后补充、停止/重启、外部来源撤权。不得为恢复覆盖用户文件或重写已有提交。

后续阶段：任务预算与长任务控制、可复用团队模板。MSE 仅在完成后记录已验证经验。
