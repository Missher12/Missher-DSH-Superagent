> **For agentic workers:** 使用 superpowers:executing-plans 按任务执行。用户于 2026-11-14 已明确授权开始改造；未经用户明确要求，不启动 Codex 子代理。

**状态：** 2026-11-14 本轮已完成。1.10.7 已发布源码及安装包，日常 DSH 已原位更新；层级团队、循环返工和外部来源通过本轮真实验收，7 条完工经验已写入 MSE 并回读。历史版本见 [completion-plan.md](completion-plan.md)。

**Architecture:** 复用现有总指挥、工单、会话、来源授权与持久化队列，由 SuperAgent 管理团队执行与回流。MSE 用于完工后保存经验；本次不新增学习接口、自动策略评测或代码自改进系统。

**Tech Stack:** 现有 TypeScript、React、Cordis、SQLite、DSH 原生会话和工具；MSE 沿用其 JavaScript 原生事件适配与学习库。

**Spec:** 本文件“目标结构”“完工后将改进点写入 MSE”构成本轮设计；基线事实以当前源码及下列审查结果为准。既有自我改进研究留作备查，不列入本次开发范围。

## 全局约束

- 保留原插件实例、配置、任务、会话、文件、连接与私人数据；旧任务不强制改造成新团队。
- 遵守项目 AGENTS.md 的 DSH 原生界面方向；不新增玻璃皮肤、最外层卡片或公共宿主样式。
- 所有成员仍是 SuperAgent 管理的真实 DSH 会话，使用现有 worker 槽、暂停和停止机制，不通过原生委派绕过调度。

## 目标结构

    你 / 飞书 / GitHub / MCP
              ↓
    总指挥：接单、目标、资源边界、最终交付
              ↓
    策划：拆解任务、分工、调整计划
              ↓
    前端 / 后端 / 检验 / 手动新增的成员或小组
              ↓
    检验报告 → 策划复核 → 总指挥交付 → 原入口回传
                   ↓ 不通过
             将具体问题退给相关成员，进入下一轮

- 总指挥复用 Runtime.masterId；每个团队现有协调会话演进为项目策划。先完成这一层，再允许策划下增加负责小组的管理成员。
- 组织关系是无环的上下级树；每轮的执行依赖仍是无环图。返工通过新轮次和明确的复核决定表达，不取消现有循环依赖校验。
- 策划节点提供“添加成员”，允许用户指定职责、模型、思考强度和前置交付。策划可分派已获授权的成员；超出任务资源边界的增员另行说明。
- 每轮有身份、计划版本、输入版本和证据引用。只有受影响成员及其下游重新执行，其余合格交付保留。
- 检验结果包含通过、返工或受阻，返工必须带目标成员与具体问题。旧计划、旧输入下的检验不能完成新一轮任务。
- 开始前确定任务资源与返工边界。主动停止、缺权限、缺关键信息和预算耗尽各自保留原因；持续无进展不无限循环。
- 前后端共享目录时保持现有串行策略；真正并行改代码使用独立工作树，并在同一轮检验前完成集成。不能将排队显示为同时执行。
- 飞书、GitHub、MCP 和本地入口采用同一套团队流程，并保留原来源、请求幂等键、主工单和结果回传位置。

## 完工后将改进点写入 MSE

**用户于 2026-11-14 澄清：先做完 SuperAgent 升级，再把改进的点写入 MSE。** 本次不改造 MSE，也不开发新的在线学习接口或通用自我改进系统。

流程为：完成开发 → 实际验收 → 复盘已验证的改进点 → 写入 MSE → 核对已保存内容。

每条经验保留以下信息：

- **问题与条件：** 原来在哪个模块、哪种情况下失败或使用不便，适用项目和版本是什么。
- **有效改进：** 实际采用的修复或工作方法，以及必要的操作步骤。
- **验证依据：** 对应代码、测试或真实宿主结果；明确哪些已经验证，哪些仍不确定。
- **复用边界：** 后续什么情况下适用，哪些条件下不能套用，避免把一次性需求写成通用规则。

只在完成并验收后记录实际有效的改进。不将当前待办清单、设计设想或尚未验证的修复写成成功经验，也不把整段开发日志直接塞入学习库。

写入沿用 MSE 实际可用的保存/学习途径，保留来源与范围并核对保存结果，不直接覆盖库文件。如果现有途径无法完成，保留整理好的待写入条目并明确报告卡点；不为这一步擅自扩成 MSE 改造，也不声称已经入库。
