# 通过 MCP 派任务

Superagent 提供本机 MCP 服务，让编辑器或其他支持 MCP 的应用派任务。使用官方 TypeScript SDK 的 Streamable HTTP；桌面应用可使用随插件附带的 stdio 连接程序。

## 接入

1. 保持 DSH 打开，在 **Superagent → 工作区** 添加需要使用的项目。
2. 打开 **设置 → MCP 接入 → 新增连接**，填写应用名并选择允许访问的工作区。
3. 保存后可先点 **测试连接**，验证所选连接方式、工具和工作区授权；再复制生成的 MCP 配置，粘贴到目标应用的 MCP 设置中。推荐本机 stdio 配置：它会读取当前 DSH 端口，重启后不必重新复制地址。
4. 在目标应用中明确要求：通过 Superagent 的 `workspace_list` 选择项目，然后调用 `task_create` 派出任务，再用 `task_get` 查询执行进度和结果。

令牌仅在创建或重置时显示，DSH 只保存其摘要。每个应用单独创建连接；启停、修改工作区或撤销在同一设置页操作。已有任务仍保留在 DSH 中。撤销连接不撤销已写文件，也不等于停止已授权任务；要停止执行，请打开对应任务点击停止。

## 工具

| 工具 | 用途 |
| --- | --- |
| `workspace_list` | 列出此连接获准的工作区及 ID |
| `task_create` | 提交 `workspaceId`、`instructions`、稳定的 `requestId`，可选 `title` |
| `task_get` | 读取阶段、执行会话、工作报告及回复；`waitSeconds` 可等待 0–30 秒 |
| `task_list` | 分页读取此连接自己的任务 |
| `task_followup` | 用 `ticketId`、稳定的 `requestId`、`text` 补充要求或回答问题 |
| `task_stop` | 停止自己的任务；保留已写文件 |
| `task_retry` | 用稳定的 `requestId` 明确重试失败任务；人工停止的任务须新建 |

创建成功只表示接单，不能当作完成。客户端应读取 `stage` 和 `summary` 判断实际结果；DSH 全局暂停时可以接单，任务保持排队。网络中断后沿用原 `requestId` 重试同一个请求；更换请求内容时使用新 ID，避免重复执行。

## 运行边界

只使用 DSH 已登记且由本机用户勾选的工作区。客户端不能传入任意目录、选择权限预设或读取其他连接的任务。工作区及具名权限在接单时固定；同一目录的本地与外部任务依次执行。任务执行沿用 DSH 默认权限，提交、推送、发布和子代理仍需任务中的明确授权。

服务复用 DSH 的本机 HTTP 端口，不另起监听器或修改其他应用配置。HTTP 地址为 `http://127.0.0.1:<当前端口>/superagent/mcp`，使用 `Authorization: Bearer <令牌>`。直接 HTTP 客户端需要在 DSH 端口改变后更新地址；stdio 配置会在下一次调用时读取新端口。

DSH 退出后任务暂停；stdio 程序本身不承担执行。关闭客户端连接只断开查询，不会停止 DSH 中的任务。此入口用于外部派单，不会自动把外部应用的全部 MCP 工具授予执行会话。
