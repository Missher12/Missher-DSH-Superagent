# DSH 本地任务版

本项目基于 DeepSeek Harness 团队的 MIT 研究原型适配。保留原型的工单、授权、执行器、持久化投递及恢复机制；默认仅启用 DSH 本地派单。

## 使用

在 DSH 插件管理器安装本项目的 `.tgz` 后，打开侧栏 **Superagent → 任务 → 新建任务**，填写任务要求，默认根据标题在 Superagent 工作区中自动创建独立目录；也可切换为“现有项目”，选择已有 DSH 工作区或填写已有项目的绝对路径。标题可留空自动生成，未派出的草稿在当前浏览器会话内保留。新建任务弹窗可选择模型；工作台的会话工具栏也可切换模型，运行中在下一步请求生效，选择仅保存在该会话，不改变 DSH 全局默认模型。也可在现有 DSH 会话中明确要求“把这个任务交给 Superagent 后台执行”，由 `superagent_task` 工具派单。

聊天派单继承来源会话的具名权限预设，面板派单使用当前 DSH 默认权限。无法继承的自定义权限会明确拒绝派单，不会自行扩大权限。默认同时执行一个任务；普通开发请求仍由当前会话直接处理。在“设置”中可以选择新任务的模型及并发数，同一目录始终依次执行。

每个任务有独立执行会话，可在自动创建的任务目录或所选的现有项目中操作。任务会读取项目的 `AGENTS.md`，保留无关改动。只有任务明确要求时才提交、推送、发布或创建子代理。

面板包含“工作台、任务、工作区、设置、帮助”五个页面。在工作台选择成员，即可在 Superagent 内查看原生执行会话；输入区将补充要求持久化后交给对应任务。未读补充要求会阻止旧一轮的 ready 报告结束任务，读取并处理后再完成。可在任务页补充要求、查看最新结果、复制结果、重试失败任务或停止任务；完整执行过程可在任务会话中查看，原始要求和历史记录折叠保留。任务记录复用上游派工展示，包含每次派工的状态、时间和恢复原因，并显示输入的送达状态及恢复说明。聊天派单的结果也回到来源会话。已完成的任务可以补充下一步要求继续执行。手动停止的任务不会被自动恢复；“重新派单”先填好草稿，由你明确发送。DSH 关闭后不继续运行，重启后恢复任务记录和未完成的执行。

设置中的“提示词”默认折叠，展开后复用上游的编辑器、完整预览、差异比较和版本历史。提示词草稿与模型、并发设置分开保存；内置执行说明的“恢复默认”使用本地模式的默认约定。提示词编辑不会改变宿主权限或启用外部任务来源。

本地模式不要求 GitHub 或飞书账号，不修改进程级 PATH、Git 配置或账号凭据。不需要额外安装 DSH CLI、GitHub CLI 或 tmux。

## MCP 与来源扩展

### 团队协作工作台

在工作台“新建任务”选择团队协作，可编辑 2–6 名执行成员的分工、模型和交付依赖。协调成员是实际执行会话：先核对计划，再派出无前置依赖的成员；下游收到前置成员的真实报告与交付记录后才创建执行任务。成员默认继承团队模型，同目录任务依次执行，沿用首次派单捕获的具名权限。

协调的规划回合结束只表示规划完成。全部成员交付后，同一个协调会话收到最终复核要求；新的复核回合完成，才显示“目标完成”。给上游成员补充要求后，下游会重新复核新的交付，再由协调汇总。给协调成员补充消息只交给该协调会话，不会擅自改变已确认的成员分工。

工作台左侧切换任务，中间显示成员原生会话，右侧查看协作关系、成员分工与完成条件。可以同时打开多个任务，逐个关闭或关闭全部工作区；关闭只收起视图，任务、文件和会话继续保留。全部关闭后显示“请打开一个工作区”，下方任务卡片可以重新打开。布局按插件实际可用宽高适配：窄窗口使用任务选择器，更窄时切换“会话 / 团队”，输入框保持在当前面板内。会话下方的活动显示一行近况，点击查看最近记录的简短摘要；完整报告仍在任务详情与原生会话中。

“添加成员”可补充执行成员、模型、思考强度和交付依赖，总计最多 6 名执行成员。实线连接已派出的真实任务，虚线表示明确填写的依赖；下游实际运行时，光点沿已交接的路径移动，卡片保持静止。原生输入保留 `/` 命令和已安装的思考强度插件。文件夹旁的三横按钮查看本任务交付文件；上下文和费用统计在仪表盘查看。

在会话中输入的补充要求会同步记录为未读任务输入，沿用原消息及附件，不重复投递；任务刚完成时的新要求会重新打开该任务。完成条件分别显示成员交付、协调最终复核和交付记录；缺少正式交付记录、文件失效或存在失败检查时不会自动判定新的团队已完成。未执行的检查及未验证事项继续列出。

执行成员可在 `orchestrator_report.delivery` 中报告 `files`、`checks` 与 `unverified`。文件必须位于真实任务目录中，完成报告不能列不存在的文件；预览只允许已报告的文件，限制前 128 KB。检查中的 `command` 与本轮实际执行结束的 bash/pwsh 调用完全匹配，界面明确标为成员报告结果。没有结构化记录时显示未提供，不推断通过；原始执行会话保留完整上下文。历史单成员任务和外部 MCP/GitHub/飞书派单仍通过原有单任务入口处理，不会被拼成团队。

任务、工作区、设置与提示词编辑器共用紧凑页头和可滚动内容区，短窗口不再要求 600px 的最小内容高度。切回工作台恢复所选任务及成员，关闭全部后保持空白。工作区支持名称和路径搜索，缩略显示长路径；完整路径保留在悬停提示中。活动默认一行摘要，完整会话与原始报告保留。

其他应用派单已提供独立的 [MCP 接入教程](mcp.md)，在 Superagent「设置 → 连接与定制 → MCP 外部派单」管理每个应用的授权。

`@missher/dsh-superagent/sources` 导出 `SourceKind`、`SourceHost`、`SourceContext`、`Trigger`、`OutboundMessage` 以及持久化键工具。其他 DSH 插件可以：

1. 注入 `orchestrator` 服务。
2. 通过 `ctx.orchestrator.sources.register(kind)` 注册实际实现的任务来源。
3. 用 `ctx.orchestrator.context(kind).receive(trigger)` 投递事件，按原生来源身份配置授权，使用稳定事件 ID 防止重复派单。
4. 实现 SourceKind 的 `channel.send` 回传结果，使用 `scope`、`policy` 和 `threadContext` 分别提供接收范围、授权及上下文。

Git 仓库事件和 MCP 工具调用转换为同一 Trigger。来源通过 `workspace(trigger, config)` 返回从可信配置取得的目录和具名权限；执行器接单时固定绑定，并按目录串行。仅有事件正文不能授予执行权限。

适配插件可直接导入公开入口；它同时声明 `ctx.orchestrator` 的服务类型：

```ts
import type { Context } from '@deepseek-ai/cordis'
import type { SourceKind } from '@missher/dsh-superagent/sources'

export const inject = ['orchestrator']
export function registerSource(ctx: Context, source: SourceKind) {
  return ctx.orchestrator.sources.register(source)
}
```

GitHub、飞书是默认禁用的可选来源组件。本地模式可以直接启用组件，在「设置 → GitHub 与飞书」配置现有项目，无需切换 `mode`。GitHub 需要账号 CLI、仓库及其本地 checkout，origin 的读取与推送地址都须对应监听仓库；飞书需要已就绪的 bot CLI 和目标工作区。接收范围与允许派单的身份在「外部派单规则」配置。已有 GitHub 任务的实例不能直接改绑另一仓库，测试应使用独立实例。

使用 GitHub 精细令牌时关闭高级设置中的「账号通知」，改用已配置仓库的 Issue、PR 和评论轮询。令牌应仅授权目标仓库所需的代码、Issue、PR 和 Actions 权限。精细令牌无法读取 Checks，CI 读取会改用完整分页的 Actions 运行、作业与提交状态，并标明仅覆盖这个范围；其他应用的 Checks 不因此被视为已验证。没有结果显示「暂无结果」，读取失败不会当作通过。账号与权限不完整时不能启用连接，其他来源不受影响。

## 开发与验证

开发包替换后，需通过 DSH 插件管理器关闭并重新启用 `dsh-superagent` 主组件，让运行中的后端重新加载；整个组合包、已有配置与任务记录继续保留。当前宿主支持通过 `pluginManager.setPluginEnabled` 对同一个主组件完成此操作。安装包版本、界面资源和运行中的后端应分开确认，不能仅以 CLI 安装成功判断更新已生效。

目标宿主 DSH `0.2.1-rc.4`，Node `24`。运行 `pnpm check` 检查类型、测试、构建及独立适配插件的类型导入，`pnpm pack --pack-destination dist` 生成安装包。开发构建可使用标准 Node；宿主加载仍需另用 DSH 的签名运行时检查。

上游的 `docs/000` 至 `008` 说明原始 GitHub 部署及通用引擎；本地使用方式以本页为准。

## 与公开原型的对齐

当前参考 [上游公开版本 8c32a9d](https://github.com/deepseek-ai/dsh-superagent-prototype/commit/8c32a9dc5d72c033816c6a8110b37f40cf94fba4)。本地版直接复用原型的引擎，按本地工作流补齐入口；不以外观相似度代替执行能力。

| 对齐项 | 本地实现与验证入口 |
| --- | --- |
| 工单、授权、输入、派工与恢复 | 保留 `src/core` 引擎；`tests/local-tasks.spec.ts` 覆盖显式派单、去重、停止、继续、目录串行和重启恢复。 |
| 精确运行状态 | 看板按 `ticketStage` 分开排队、运行、需人工处理、等待触发和结束；等待分区无任务时隐藏。 |
| 提示词与版本 | 复用上游编辑器、预览、历史与冲突处理；面板和代理读取资源使用同一套本地默认约定。 |
| 来源与执行记录 | 任务详情折叠保留派单依据、策略版本、派工状态及输入送达记录；原生会话提供完整执行步骤。 |
| 健康与结果回传 | 运行错误逐项显示，有错误时不显示“就绪”；沿用持久化结果投递与去重。 |
| 插件扩展 | 保留上游 SourceKind 边界，公开 `sources` 类型入口；MCP 已完成真实派单验收，GitHub/飞书可选组件的实接状态见完成记录。 |

保留的本地差异：支持按任务标题创建独立目录，或在用户选择的已有工作区执行，按目录串行；沿用 DSH 的具名权限；日常面板保留“工作台、任务、工作区、设置、帮助”。原型默认准备独立工单目录并面向 GitHub 协作，本地版不会自动创建 Git worktree、接入外部账号或扩大权限。

实际安装版本与各来源的验收证据以 [完成记录](completion-plan.md) 为准。标准 Node 测试、宿主加载和真实外部来源验收分别记录，不能互相替代。
